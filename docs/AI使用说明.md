# AI 工具使用说明

> 赛事要求如实说明 AI 在项目中承担的工作。这份文档尽量写具体，不含糊。

## 一、用了哪些工具

| 工具 | 用途 |
| --- | --- |
| **DeepSeek Harness**（本次主要工具） | 需求拆解、数据建模、代码生成、界面调试、自动化测试、文档撰写 |
| 浏览器开发者工具（Chrome Headless） | 截图核验界面、检查控制台报错、跑界面自测 |
| Node.js | 跑引擎层的单元断言（不参与最终交付） |

## 二、AI 在各个环节具体做了什么

### 1. 需求分析与建模

- **人**：确定"家庭/宿舍用药安全"这个方向，阅读赛事评分标准与提交规范，确认 34 小时时间窗与提交形式。
- **AI**：把"用药安全"拆成可落地的四类可计算问题（重复成分 / 相互作用 / 人群禁忌 / 每日总量），
  并提出以**成分**而非药品作为建模起点——这个决定直接让"不同药名、相同成分"能被自动识别。
- 产出：`docs/开发日志.md` 里的数据模型说明。

### 2. 药品知识库

- **AI**：整理 31 种常见药、30 个成分、25 条成分级相互作用、4 条间隔规则、5 类人群提示，
  按「药品 → 成分」的结构写成 `assets/js/data.js`。
- **人**：抽样核对成分与常见风险描述（如藿香正气水含乙醇、头孢 + 酒精的双硫仑样反应），
  确认表述没有夸张。

### 3. 代码生成

- **AI**：生成 `engine.js`（风险分析与排程算法）、`graph.js`（手写力导向布局）、
  `voice.js`（Web Speech 封装）、`app.js`（状态与交互）与全部 CSS。
- 生成不是一次成型：排程算法第一版采用"固定偏移 + 局部挪动"，在实际药箱里会产生 12 条无法消除的冲突；
  后来改成"全局搜索最小代价位置"，冲突降为 0。这个过程记录在开发日志里。

### 4. 调试与验证

- **AI**：用 Chrome Headless 反复截图核验界面（空状态、风险页、时间表、图谱），
  通过控制台日志确认没有 JS 报错；
  写了一套 `tests/ui-selftest.html`，用真实点击驱动界面并断言 14 项行为。
- **AI**：发现并修复了两个问题——评分环在空药箱时显示成满分、切换到图谱页时因 `requestAnimationFrame`
  延迟导致首帧为空。

### 5. 文档

- **AI**：起草 README、本说明、演示脚本与开发日志。
- **人**：核对团队分工、比赛信息、最终提交材料。

## 三、人工把关的部分

需要说明的是，以下判断由人来负责，AI 只提供候选：

1. **选题与范围**：做哪一类产品、砍掉哪些功能（如不做诊断、不做处方建议）。
2. **医学表述**：风险描述是否准确、免责声明怎么写。
3. **参赛合规**：确认所有代码在比赛窗口内产生、AI 使用如实披露、不搬运现成作品。
4. **演示与答辩**：现场怎么讲、可能被问什么。

## 四、关于"AI 生成代码"的说明

本项目没有隐藏 AI 的使用，也不打算隐藏。赛事评分标准里明确写了
"不以手写代码数量、使用特定 AI 工具或 AI 生成代码比例额外加减分"，
所以我们把精力放在**把问题想清楚、把功能做扎实、把话说清楚**上。

如果评委问到某段代码为什么这么写，我们能从数据结构、算法选择、遇到的坑三个层面解释，
而不是"AI 写的，我不知道"。
