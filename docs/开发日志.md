## 关键决策

### 决策一：为什么以「成分」而不是「药」建模

最初想直接维护"药 × 药"的禁忌表。很快发现不行：31 种药两两组合是 465 对，
每新增一种药都要补 30 条规则，而且同一种成分会被重复描述几十遍。

换成"药 → 成分"，并让风险规则只写在成分对上之后：

- 规则数量从 N² 降到 M²（这里 M=30，实际只写了 25 条有价值的）；
- "感康 + 泰诺林"这种**不同药名、相同成分**的情况能被自动抓出来，而不是靠人预先枚举；
- 换个商品名、换个厂家，只要成分一样，检测照样生效。

这是整个项目最重要的一次建模选择。

### 决策二：纯原生，不引框架

评委要能"打开就看"，而不是先 `npm install`。所以：

- 不用 React/Vue，用 `app.js` 手写状态 + 渲染；
- 不引 d3，手写一个 60 行的力导向布局；
- 不用构建工具，`index.html` 里按顺序引 5 个 classic script。

代价是代码量稍多，好处是**零依赖、零构建、断网可用**，而且任何一台电脑双击就能演示。

### 决策三：视觉上做"医疗感"，不做"工具感"

配色用青绿（#0e9f8e）而不是常见的蓝色医疗模板；风险用红 / 橙 / 蓝三级色阶；
时间表做成纵向时间轴而不是表格——表格看起来像后台管理系统，时间轴才像"一天的安排"。

## 踩过的坑

### 坑一：排程算法第一版不收敛

**现象**：用「感康 + 泰诺林 + 头孢 + 藿香 + 蒙脱石」测试，第一版算法报出 **12 条**无法满足的间隔冲突。

**原因**：第一版是"局部挪动"——发现冲突就把其中一剂按固定偏移量（±2h、±3h）推一下。
但推完可能又撞上第三种药，而候选位置只有几个固定档位，很容易走进死胡同。

**改法**：改成"全局搜索最小代价位置"——在 06:00–23:00 之间以 15 分钟为步长遍历所有位置，
过滤掉违反约束的，再从剩下的里面挑代价最小的（代价 = 偏离原定时间 + 拥挤惩罚）。

**结果**：同样的药箱，冲突从 12 条降到 **0 条**。

### 坑二：空药箱时评分环显示成"满分"

**现象**：药箱为空时，安全分显示 `--`，但外圈是完整的绿色圆弧，看起来像"100 分"。

**原因**：空药箱没有风险，扣分为 0，`score = 100`，圆弧被画满。

**改法**：空药箱时不画进度（进度归零、描边置灰），只有真的有药时才计算分数。

### 坑三：切到图谱页，第一帧是空的

**现象**：点「关系图谱」标签后，SVG 里什么都没有，再点一次才出来。

**原因**：切换标签时用 `requestAnimationFrame` 延后渲染，但画面在下一帧之前就被截取了
（自动化测试里尤为明显）。

**改法**：标签的显示状态是同步改的，直接同步渲染即可，去掉 rAF。

### 坑四：中文标题在节点圆里被截断

**现象**：图谱里药名塞进半径 21 的圆，"复方氨酚烷胺"四个字被截成"复方氨酚"还溢出圆边。

**改法**：改用"圆 + 下方标签"的样式，圆里只放一个小白点作为"药丸"意象，
标签放全名；并且优先显示**品牌名**（感康、泰诺林、西力士、思密达），比通用名更短、更好认。

## 验证方式

### 引擎层（Node 断言）

```js
// 输入 8 种药，检查风险命中与排程收敛
const cart = ['fenbid','gankang','ganmaoling','huoxiang',
              'cefuroxime_tab','smecta','euthyrox','caltrate'];
analyze(cart, { population: 'elderly' })
// → high: 5, medium: 3, score: 15
schedule(cart)
// → 7 个时间点、16 剂、0 条残留冲突
```

重点验证了三个必须命中的规则：

1. 头孢呋辛 + 藿香正气水 → 双硫仑样反应（high）
2. 感康 + 感冒灵 → 对乙酰氨基酚重复（high）
3. 蒙脱石散 + 左甲状腺素 → 需间隔 2 小时（排程后错开）
